# Product

## Register

brand

## Users

People who run (or are deciding whether to run) a Linux Wayland desktop — Niri or Hyprland
users, ricers, terminal dwellers, and the curious arriving from a screenshot. They land on the
site to answer one question fast: *what is iNiR and do I want it?* Then a second audience —
people already running it — return to the docs to install, configure, theme, and troubleshoot.

## Product Purpose

iNiR is a complete desktop shell for Niri (built on Quickshell): bar, dock, sidebars,
notifications, settings, theming, lock screen — one runtime, not a theme or dotfiles. The
website is the public face: a landing that sells the ambition and craft of the project, plus a
documentation reader that makes the existing markdown wiki feel like part of the product instead
of a generic mkdocs theme. Success = a visitor immediately understands this is bespoke,
serious, and beautiful, and finds the install path without friction.

## Brand Personality

Warm, technical, anime-adjacent. Voice: a calm documentation portal for a serious Linux tool,
with the atmosphere of a beautifully illustrated desktop scene rather than a generic developer
landing page. Three words: **warmth, focus, craft.** The site should feel approachable and
visually charming without becoming childish, literal-Japanese, or template-like. Emotion: a
visitor should feel that iNiR is both powerful and carefully cared for.

## Anti-references

- Generic mkdocs Material with a purple accent.
- SaaS-cream landing pages, soft rounded cards with an icon + heading + paragraph repeated.
- Literal Japanese theming as decoration: random kanji, shrine/postcard tropes, or cultural cosplay.
- Pure carbon-console darkness as the only brand mode; the website now needs both warm light mode
  and a rich dark mode.
- Glassmorphism-as-decoration, gradient text, hero-metric template, tiny tracked eyebrow on
  every section.

## Design Principles

1. **Reference-faithful structure.** The supplied reference image is the north star for layout:
   fixed dark rail, calm topbar, hero illustration scene, compact docs dashboard, and composed footer.
2. **Anime-adjacent, not literal Japanese.** Warm illustrated mood, soft paper/ink surfaces,
   mascot energy, and calm focus — but no cultural cosplay or random Japanese text.
3. **Presentation and documentation are one surface.** The landing should sell the project and
   immediately become a docs portal; docs must feel first-class, not a separate generic theme.
4. **Light and dark are both designed.** Light mode is warm and welcoming; dark mode is rich and
   focused. Neither is an afterthought.
5. **Craft over cards.** Cards exist because the reference is a documentation dashboard, but they
   must vary in size, hierarchy, and rhythm instead of becoming a generic repeated grid.

## Accessibility & Inclusion

WCAG AA: body text must hit ≥4.5:1 in both light and dark modes. Placeholder text must remain
readable, not pale gray. Theme switching must preserve content and keyboard focus. Full
`prefers-reduced-motion` alternative: motion enhances already-visible content and never gates it.
Documentation navigation, search, theme toggle, copy buttons, and mobile menus must be keyboard
reachable.
